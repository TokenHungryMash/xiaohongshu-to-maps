# 轻量进度记录

默认只记录能帮助恢复和防遗漏的信息，不要求完整 v2 数据库。已有详细台账沿用，不重新迁移或补齐空字段。

可用一个 JSON 或简短 Markdown：
- 专辑、处理范围、目标清单名称和链接。
- 笔记标题或标识、读取是否完成、必要材料文件、读取失败原因。
- 地点原名或地图名、来源标题、处理结果（已保存／待确认／重复／非地点），备注文字。
- 待确认地点记录原因类别、具体疑点、已找到候选数量及分店/区域、数量是否完整、用户选择和筛选依据；保存失败写一句原因。

完成时核对范围内没有静默漏篇或未处理的明确地点，清单数量与独立已保存地点数对应。备注集中回读一次即可；能批量读时批量读，不能时利用已观察的保存证据并如实说明验证限制。链接缺失、报错或无预览不计为失败。只补失败项一次，不为形式完善记录反工。

用户明确要求结构化数据库或严格溯源时，才扩展原名、来源片段、匹配证据、地图标识和验证时间等字段；没有证据不能标成已验证。
