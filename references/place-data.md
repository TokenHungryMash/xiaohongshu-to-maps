# 轻量进度记录

默认只记录能帮助恢复和防遗漏的信息，不要求完整 v2 数据库。已有详细台账沿用，不重新迁移或补齐空字段。

可用一个 JSON 或简短 Markdown：
- 专辑、处理范围、目标清单名称和链接。
- 笔记标题或标识、是否有本轮返回、必要材料文件、读取失败或已知缺口；区分标题覆盖与全文核验。
- 准备／附卡、读取／续写、集中整理／校对、清单文件生成及开始输出对话的实际时间节点，简单记录即可；未知的最终显示时间不编造。
- 地点原名或地图名、来源标题、处理结果（待导入／已保存／待确认／重复／非地点），备注文字。单品注明所属店铺；无法归属时单独记录为非地点的“未归属单品线索”，保留已有上下文和来源，不计入地点或待确认店铺数。
- 仅预览或等待确认时记录停止点及预览文件，不把待导入写成已保存；重新测试的材料单独存放，不混入历史返回。
- 分店筛选记录保留／排除理由及旅行范围、品牌、核实到的门店名称/地址、笔记提及门店或同品牌分店、来源及保存结果；仅作者分店不明不列待确认。排除项记录停业、重复或范围外等原因，不计作待确认。
- 待确认地点记录原因类别、具体疑点、已找到候选数量及分店/区域、数量是否完整、用户选择和筛选依据；保存失败写一句原因。

预览完成时集中检查四列清单覆盖全部有效记录和完整来源标题、分类数量一致、明显误合并已修正；抽看简介能否说明地点是什么，评价能否看出作者喜欢或不满意的对象，压缩时没有丢掉关键单品、负面意见、分歧或分店疑点；少量遗漏或未确认项如实标注，不追求逐视频零遗漏，不反复补问。导入完成时核对用户已确认范围内的明确地点处理结果与独立已保存地点数。备注记录保留实际换行；验收检查“小红书／来源”两段仍存在、没有简介，来源标题与原文一致，或为原标题连续前缀加“…”且未改写，编号能对应完整来源。备注集中回读一次即可；能批量读时批量读，不能时利用已观察的保存证据并如实说明验证限制。地图默认不附来源链接；用户要求附链接时，来源跳转报错单独记为链接失败，不能宣称全链路已验证。无预览与打不开须区分。只补失败项一次，不为形式完善记录反工。

用户明确要求结构化数据库或严格溯源时，才扩展原名、来源片段、匹配证据、地图标识和验证时间等字段；没有证据不能标成已验证。
分类清单分别记录大类、名称、目标图标、实际设置方式（原生图标／仅名称emoji／未设置）、重开或刷新后的验证结果（已确认／失败／未验证）、链接与实际保存数；无障碍文本仅有“修改图标”按钮不能作为具体图标已保存的证据。地点记录地图名称/地址、所属清单、最终备注和保存/回读证据。保存用户已确认范围，恢复同一清单，不重复创建。

保留稳定笔记编号、完整标题、实际取得的来源链接及验证状态；地图显示原标题或“原标题连续前缀＋…”，可回查完整标题，不得将改写标题当作截断标题。住宿标记为仅知识库，不计入地图待导入或失败数量。仅当用户要求地图附来源链接并启用链接流程时，记录链接样例的取得方式、从地图打开结果与对应笔记；其他链接未逐条打开时如实标记，不能继承样例的已验证状态。

对话摘要与详细知识库由同一完整记录生成；保存摘要字段时保留详细字段和原有来源资料，不用短摘要回写覆盖。验收同时核对全部记录覆盖、观点方向一致、详细版资料未因界面精简而丢失。
